# Patch Verification Design

Validate patches generated by `oss-bugfix-crs`. Given CRS-generated patches, verify they correctly fix vulnerabilities without breaking functionality.

## CRS Output Directory Structure

CRS must write its outputs to `/artifacts/` in the container. CRSBench will snapshot this directory periodically for evaluation.

**Required output structure:**

```
/artifacts/                     # CRS output directory (container)
├── patches/                    # Generated patches (required for patch generation CRS)
│   ├── pov_0/                  # Patches for pov_0
│   │   └── patch.diff          # Unified diff format
│   ├── pov_1/                  # Patches for pov_1
│   │   └── patch.diff
│   └── pov_2/                  # Patches for pov_2
│       └── patch.diff
└── crs-data/                   # CRS-specific outputs (optional)
    ├── patch-analysis.json     # Any additional data CRS wants to record
    ├── repair-attempts.log
    └── test-results.json
```

## POV Variant Structure

POV variants are stored in the benchmark's `.aixcc` directory:

```
benchmarks/<project>/.aixcc/
└── <harness>/
    └── <cpv_id>/
        ├── blobs/
        │   ├── pov_0.blob    # Original ground truth POV
        │   ├── pov_1.blob    # Variant 1
        │   ├── pov_2.blob    # Variant 2
        │   └── ...
        └── patches/          # Ground truth patches
            ├── patch_0.diff
            ├── patch_1.diff
            └── ...
```

## Patch File Requirements

| Requirement | Description |
|-------------|-------------|
| **Location** | `/artifacts/patches/<pov_id>/patch.diff` |
| **Format** | Unified diff format |
| **Naming** | Each POV gets its own subdirectory named after the POV ID |
| **File name** | The patch file is always named `patch.diff` within each POV directory |

## Verification Pipeline

```
CRS Patch Output
      │
      ▼
┌─────────────────────────────────────────────────────────┐
│              Patch Verification Pipeline                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  0. Pre-cache (repo clone, inc-image pull)             │
│         │                                               │
│         ▼                                               │
│  1. Apply Patch (git apply)                            │
│         │                                               │
│         ▼                                               │
│  2. Incremental Build (inc-build image)                │
│         │  (or fallback to standard OSS-Fuzz build)    │
│         │                                               │
│         ▼                                               │
│  3. POV Variant Tests ─────────► Must NOT crash        │
│         │  (parallel execution across all CPVs)        │
│         │                                               │
│         ▼                                               │
│  4. Unit Tests                                          │
│         ├─► full: Run all tests                        │
│         └─► rts: Run only patch-affected tests         │
│         │                                               │
│         ▼                                               │
│  Verification Result: PASS / FAIL                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

| Step | Description | Pass Criteria |
|------|-------------|---------------|
| Pre-cache | Clone repo and pull inc-image before parallel execution | Reduces parallel contention |
| Apply Patch | Apply unified diff with `git apply` | Patch applies cleanly |
| Incremental Build | Build using inc-build Docker image | Build succeeds |
| POV Variant Tests | Run all POV variants from blobs directory | No crash on any variant |
| Unit Tests | Run tests based on selected mode | All tests pass |

## Verification Status

| Status | Description |
|--------|-------------|
| `PENDING` | Verification not yet started |
| `BUILD_FAILED` | Patch could not be applied or build failed |
| `POV_STILL_TRIGGERS` | One or more POV variants still crash |
| `TEST_FAILED` | Unit tests failed |
| `VALID` | Patch is valid (fixes bug without breaking tests) |
| `ERROR` | Verification failed due to an error |

## Security Verdict

Each patch receives a binary security verdict:

| Verdict | Criteria |
|---------|----------|
| `PASS` | At least one CPV fully fixed (all variants pass) AND unit tests pass |
| `FAIL` | No CPVs fully fixed OR unit tests fail |

## Per-CPV Statistics

For each CPV tested, the engine tracks:

```python
@dataclass
class CpvStats:
    cpv_id: str                      # e.g., "cpv_0"
    variants_tested: int             # Number of POV variants tested
    variants_matched: int            # Number of variants fixed
    variant_results: dict[str, bool] # Per-variant pass/fail

    @property
    def status(self) -> str:
        # "complete" if all variants pass
        # "partial" if some variants pass
        # "none" if zero variants pass
```

## Test Mode Options

User selects one of the following modes for unit test validation (default: `full`):

| Mode | Description | Pros | Cons |
|------|-------------|------|------|
| `full` (default) | Run complete test suite | Complete verification | Slow |
| `rts` | Run only patch-affected tests | Fast, handles many patches | May miss edge cases |

## Incremental Build Strategy

Since bugfix CRS may generate many candidate patches, we use pre-built inc-build Docker images:

```
Inc-Build Image (pre-built)
      │
      ├──► Patch 1 ──► Incremental compile ──► Validate
      │
      ├──► Patch 2 ──► Incremental compile ──► Validate
      │
      └──► Patch N ──► Incremental compile ──► Validate
```

**Inc-build image naming:**
- Registry: `ghcr.io/team-atlanta/crsbench/<project>:inc-<sanitizer>`
- OSS-Fuzz compatible: `aixcc-afc/<project>:inc-<sanitizer>`

**Fallback behavior:**
- If inc-build image not available, falls back to standard OSS-Fuzz build
- Use `--no-inc-build` to force standard build (useful for debugging)

## Build Caching

Builds are cached to avoid redundant compilation:

- **Check**: `is_variant_built()` checks if build artifacts exist
- **Skip**: If cached, skip directly to verification
- **Force**: Use `--force-rebuild` to clean and rebuild from scratch

## CLI Interface

### Auto-Discovery Mode (Default)

```bash
# Discover and verify all patches in benchmark
crsbench patch-verify benchmarks/project

# Filter by harness
crsbench patch-verify benchmarks/project --harness html
```

### Directory Mode

```bash
# Verify patches in a directory
crsbench patch-verify benchmarks/project \
    --harness html \
    --patch-dir ./patches \
    --pov-dir ./povs
```

### Single Patch Mode

```bash
# Verify a single patch
crsbench patch-verify benchmarks/project \
    --harness html \
    --patch ./my-patch.diff \
    --pov ./pov.blob
```

### Advanced Options

```bash
# Force rebuild, disable inc-build
crsbench patch-verify benchmarks/project \
    --force-rebuild \
    --no-inc-build

# Parallel workers
crsbench patch-verify benchmarks/project \
    --build-workers 4 \
    --verify-workers 8

# Output as JSON
crsbench patch-verify benchmarks/project \
    --output results.json --format json
```

## CLI Arguments

| Argument | Description | Required |
|----------|-------------|----------|
| `benchmark_path` | Path to benchmark directory | Yes |
| `--harness` | Harness name filter (auto mode) or target (directory/single mode) | Depends |
| `--patch` | Single patch file to verify | No |
| `--patch-dir` | Directory containing patches (`<pov_id>/patch.diff`) | No |
| `--pov` | Single POV file | No |
| `--pov-dir` | Directory containing POV files | No |
| `--oss-fuzz` | Path to OSS-Fuzz directory | No (default: `./oss-fuzz`) |
| `--test-mode` | `full` or `rts` | No (default: `full`) |
| `--sanitizer` | Sanitizer type (`address`, `undefined`, `memory`) | No (default: `address`) |
| `--timeout` | POV timeout in seconds | No (default: 120) |
| `--build-timeout` | Build timeout in seconds | No (default: 1200) |
| `--test-timeout` | Unit test timeout in seconds | No (default: 1800) |
| `--build-workers` | Number of parallel workers for builds | No (default: 4) |
| `--verify-workers` | Number of parallel workers for POV tests | No (default: 4) |
| `--no-parallel` | Disable parallel patch verification | No |
| `--no-variants` | Disable POV variant verification | No |
| `--force-rebuild` | Force rebuild even if cached | No |
| `--no-inc-build` | Disable incremental builds | No |
| `--output` | Output file path | No |
| `--format` | Output format (`json`, `yaml`, `text`) | No (default: `text`) |

## Implementation

### Key Classes

- **`PatchVerificationEngine`**: Main orchestrator for patch verification
- **`PatchInfo`**: Data class for patch information
- **`PatchVerificationResult`**: Result of patch verification
- **`PatchVerificationStatus`**: Enum for verification status
- **`CpvStats`**: Per-CPV verification statistics
- **`VerificationScores`**: Aggregate scoring metrics

### Key Methods

```python
class PatchVerificationEngine:
    def verify_patch(
        self,
        benchmark_path: Path,
        patch: PatchInfo,
        harness: str,
        pov_path: Path,
    ) -> PatchVerificationResult:
        """Verify a single patch."""

    def verify_patches(
        self,
        benchmark_path: Path,
        patch_dir: Path,
        harness: str,
        pov_dir: Path,
        *,
        parallel: bool = True,
    ) -> list[PatchVerificationResult]:
        """Verify multiple patches from a directory."""

    def verify_benchmark(
        self,
        benchmark_path: Path,
        harness: Optional[str] = None,
        *,
        parallel: bool = True,
    ) -> list[PatchVerificationResult]:
        """Auto-discover and verify all patches in benchmark."""

    def _test_patch_against_all_cpvs(
        self,
        variant_name: str,
        harness: str,
        benchmark_path: Path,
    ) -> tuple[list[str], dict[str, CpvStats], VerificationScores]:
        """Test patch against all CPVs in harness."""
```

### Parallelization

Two levels of parallelization using `ThreadPoolExecutor`:

1. **Patch-level** (`build_workers`): Multiple patches built/verified in parallel
2. **POV variant-level** (`verify_workers`): Multiple POV variants tested in parallel within each patch

**Pre-caching** before parallel execution:
- Repository is cloned once and cached
- Inc-build image is pulled once and cached
- Prevents parallel workers from competing for the same resources

### Timing Metrics

Per-patch timing:
- `build_time`: Time to compile patched code
- `pov_test_time`: Time running POV tests
- `unit_test_time`: Time running unit tests
- `elapsed_seconds`: Total time for this patch

Aggregate timing:
- `wall_clock_time`: Actual elapsed time for entire run
